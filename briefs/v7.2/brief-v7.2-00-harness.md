## What to build (all in `tools/`, dependency-free beyond the Playwright every other tool uses)

1. **`audio-render.mjs`**: loads a URL headless (Chromium, autoplay allowed, as `audio-test.mjs` does), waits for `body.ready`, dispatches `begin` on `fp.events` (`window.__fp` is the ctx), resumes `fp.audio.ctx`, waits for the master fade (4.5 s), then taps `fp.audio.vol` (post-limiter) with an AudioWorklet (inline module via a Blob URL; ScriptProcessor fallback if the worklet cannot load from `file:`/`http:`) into Float32 PCM, for `--seconds` (default 20), and writes a 48 kHz (or the context's rate) stereo 16-bit WAV. Options per `harness.md`: `--cue=name[,name]` with `--at=dx,dy,dz` (camera-relative, like audio-test's offsets) and `--opts=<json>`, fired 1 s in, `--every=<s>` to repeat; `--walk=<speed>` (hold W via `fp.controls` or by dispatching keydown; steps must fire); `--steps=<n>` (call `fp.player.onStep(false)` n times at a walking cadence, standing); `--gutter` (hold `fp.sky.flicker.hold = 0.3` for the render, or whatever the field is; check `src/sky.js`); `--pre` to tap `fp.audio.master` (pre-limiter) instead, for the limiter-engagement check; `--mono`; `--seed=<n>` if the page exposes a seed param (check `main.js`; if there is none, document that renders are deterministic by pose and time instead). Also write `<out>.json`: URL, options, context sample rate, start time, and the cue log: wrap `fp.audio.cue` for the render and record every call (name, time since start, distance from the camera, opts). `?only=audio` renders must work for quick cue work, and full-world renders at a `?pos=` for the survey.
2. **`audio-metrics.mjs`**: reads a WAV (16/24/32-bit PCM and float), reports every metric in `harness.md`'s table with the definitions there (K-weighting per BS.1770: the two biquads, 400 ms blocks with 75 % overlap, absolute gate −70 LUFS and relative gate −10 LU for `lufs_i`; short-term 3 s for `lufs_s_max` and `lra`). Spectrogram PNG written with a hand-rolled PNG encoder (zlib from `node:zlib`): log-frequency 40 Hz–16 kHz, 1600 px wide for 20 s (80 px/s, scale with length), 512 px tall, fixed dB colour scale −90…−20 so pictures compare, 1 s time ticks, the cue log's events marked as labelled ticks along the top when `<wav>.json` exists beside it. `--baseline=<wav>` prints before → after → delta for every metric and writes the two spectrograms stacked in one PNG. `--json` writes `<wav>.metrics.json`. Validate the metrics on synthetic signals you generate in Node (a −20 dBFS 1 kHz sine must read −23.0 LUFS ± 0.5 per BS.1770; a loop with a seam must show `clicks` at the period; white noise's `sharp_db` must be near the band's share of the spectrum; a sine AM'd at 70 Hz must show high `rough`); put those as `tools/audio-metrics-selftest.mjs` (exit 1 on failure) and report its count.
3. **`audio-survey.json`** and **`audio-survey.mjs`**: the listening stations in `harness.md` (eleven; take `pos`/`yaw` from the places `src/settings.js` teleports to and the v5–v7 docs' render poses; name each by place). Each entry: name, url params, seconds (20), options, and the bands from `harness.md`'s table (bed-at-quiet-pose bands for the standing moor and wood poses, whole-mix bands for the walks; put `gated: true` only on `clicks`, `seam_s`, `lufs_s_max`, `sharp_db` and `gap_max_s` on moor poses for now, so the voicing agents can tighten the rest). The tool renders each in sequence (one browser, one page per pose), measures, writes `survey.md` (pose × metric, out-of-band cells marked `!`, gated failures `!!`), `survey.json`, and with `--baseline=<dir>` the before/after table. Exit 1 only on a gated failure.
4. **`audio-quality-test.mjs <base>`**: runs the survey into `shots/wip/audio/quality-<timestamp>`, then the limiter-engagement check (render the moor walk with `--pre` and without; the per-block gain difference over 1 dB for under 1 % of blocks), then the determinism check (two renders of the first pose within 0.2 dB `lufs_i`). Prints `PASS`/`FAIL` lines and a count; exit 1 on any fail. Zero checks is a failure.
5. **The baseline.** Run the survey on the current sound into `shots/wip/audio/survey-baseline/` and copy `survey.md` and `survey.json` (not WAVs or PNGs) to `briefs/v7.2/audio/baseline/`. Expect it to be red (seam clicks, sharpness); that is the point. Report the table.
6. **Docs.** `runtime.md` gets one paragraph on the four tools under the tests; `README.md` "Also here" one line; `harness.md` corrected to what you built, with real numbers from the baseline replacing any band you found wrong (say which, and why, in the report; do not loosen a band so the baseline passes).
